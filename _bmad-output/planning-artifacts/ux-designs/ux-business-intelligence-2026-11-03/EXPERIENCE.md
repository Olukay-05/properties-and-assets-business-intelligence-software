# Cloud Crafters Property & Asset Intelligence: Experience Spine

## Foundation

**Cloud Crafters Property & Asset Intelligence** is a multi-surface responsive web application serving Nigerian facilities-management (FM) providers across two primary operating environments:

1. **Desktop Editorial Canvas (`>760px`)**: Used by Operations Managers, Organisation Owners, and Platform Admins for portfolio registration (`UJ-1`), inspection scheduling, work-order oversight, audit review, and monthly Client Report compilation and export (`UJ-4`).
2. **Mobile Field Browser (`<=760px`, Android & iOS parity)**: Used on-site over variable Nigerian mobile networks by Site Supervisors (`UJ-2`), Technicians (`UJ-3`), and Contractors to execute checklists, capture GPS and photo evidence, log multi-visit maintenance progress, and close work orders.

### Technical & Architectural Posture
- **Frontend Stack**: React 19 + TypeScript 5 + Inertia 3 (`@inertiajs/react`) + Tailwind CSS 4 + `shadcn/ui` primitives reskinned to the Cloud Crafters Editorial Intelligence token set (`DESIGN.md` and `docs/design/design-context.md`). Geospatial views use a unified `<PropertyMap>` component wrapping MapLibre GL JS 5 and OpenFreeMap vector tiles (`AD-7`, `AD-20`).
- **Full-Stack Type Contract**: All Inertia page props and REST `/api/v1` payloads are backed by typed server DTOs transformed into `resources/js/types/generated` (`AD-16`). Zero business logic lives exclusively in React components or Inertia controllers (`AGENTS.md` Standing Rules 1 & 2, `AD-1`).
- **Multi-Tenant & Client-Scope Isolation**: Every request resolves tenant context (`organisation_id`, `user_id`, `role`, `client_scope`) strictly from the authenticated session (`FR-19`, `AD-3`) backed by database Row-Level Security (`AD-4`) and automatic `client_scope` filtering on all client-owned entities (`AD-5`). Forged `organisation_id` inputs in request payloads are ignored.
- **Temporal, Currency & Geographic Standard**: All timestamps are stored in UTC and rendered in the UI localized to **`Africa/Lagos` (`WAT`, `UTC+1`)** in `DD MMM YYYY, HH:mm WAT` format. Monetary values use `NGN` (`₦`) with comma thousands separators, and all distances are computed and displayed in **metres (`m`)** via PostGIS geography casts with `font-variant-numeric: tabular-nums`.

Visual identity and screen spec references: `DESIGN.md`, `docs/design/design-context.md`, [design-system-preview.html](imports/design-system-preview.html), [cloud-crafters-design-system.css](imports/cloud-crafters-design-system.css), and the four SPEC-mode screen specifications in `specs/screen-spec-*.md`. *Both UX spines (`DESIGN.md` and `EXPERIENCE.md`) win on conflict with any mock, wireframe, or imported file.*

## Information Architecture

### Navigation Chrome
- **Skip Link (WCAG 2.2 SC 2.4.1)**: Every page renders `<a href="#main-content" class="cc-skip-link">Skip to main content</a>` as the first focusable element in `<body>`.
- **Desktop (`>760px`)**: Top `app-shell-header` (`{spacing.16}` height) displaying the acting Organisation name, the Tier-2 **Client account scope switcher** (`dropdown-editorial` allowing users with multi-client or unrestricted org scope to filter the workspace to one Client Account or `All permitted client accounts`), horizontal module links (`Portfolio & properties`, `Assets`, `Inspections`, `Work orders`, `Client reports`, `Organisation & audit`), and the active user's role badge. Below the header, the `<main id="main-content" class="cc-page">` container (`{spacing.page-max}` / `1120px` max-width on `{colors.shell-backdrop}`) holds the document surface.
- **Mobile (`<=760px`)**: Compact top header showing the active Client Account badge (`>=12px` eyebrow) and a `40px x 40px` Menu button opening a slide-over navigation sheet (aliased under `modal-dialog`), paired with a persistent bottom `mobile-quick-task-bar` for field roles (`My inspections`, `My work orders`, `Asset lookup`, `Quick evidence`).
- **One Primary Action Per View & Overlay Discipline**: Every surface exposes at most **one primary button** (`.cc-button--primary` or `.cc-button--teal`), ranking secondary (`.cc-button--secondary`) and tertiary (`.cc-button--text`) actions clearly. Modal dialogs (`modal-dialog`), mobile slide-over navigation sheets, and inline action drawers stack **at most 1 level deep**. Opening a dialog or sheet on top of another overlay is banned.

## Voice and Tone

The written voice is **calm, factual, operational, and defensible**. Every label, alert, and report sentence should read like an engineering or facilities-management record that can be handed to a commercial property owner during a billing review.

### Microcopy Rules (`enterprise-ui-ux` Reference 06)
1. **Sentence Case & Plain Punctuation**: Use sentence case for all headings, buttons, form labels, tabs, and menu items. Never use em dashes or en dashes as punctuation in UI copy; use periods, colons, commas, or middots (`·`) instead.
2. **Three-Part Alert & Error Formula**: Every validation, domain, or system alert must state: **(1) What happened**, **(2) Operational impact**, and **(3) Next action**, while preserving all entered user data.
3. **Postcode Truthfulness (Hard Guardrail: PRD §6.2 & `DESIGN_SYSTEM.md` §6)**: When a Property postcode is validated via the optional server-side NIPOST check, the `.cc-status--success` badge reads `Postcode verified (NIPOST)` accompanied by the mandatory helper note: *"Identifies postal routing reference only. Does not verify property title, ownership, or legal occupancy."*
4. **Custodian vs. Technician Distinction**: Always label asset accountability as **Accountable custodian** (stored in `asset_custody`) and maintenance execution as **Assigned technician / contractor** (stored on `work_orders`).
5. **Immutability Transparency**: Approved inspections and completed work orders display a formal `.cc-status--neutral` lock notice explaining why fields are read-only and offering the exact sanctioned path (`Create corrected version` when an approved inspection requires amendment).

| Context | Do (Editorial Intelligence Voice) | Don't (Consumer / Generic SaaS Voice) |
|---|---|---|
| **Primary Buttons** | `Register asset`, `Raise maintenance request`, `Complete work order`, `Compile report preview` | `Submit`, `Go!`, `Let's get started`, `Done`, `OK` |
| **Work Order Completion Gate** | `Completion photo required. Attach at least one timestamped photo of the completed work before marking this work order Completed.` | `Error: missing file.` / `Oops! You forgot to upload a picture!` |
| **GPS Unavailable on Evidence** | `GPS coordinates unavailable on this device. Photo and timestamp are recorded. You may complete the work order without location data.` | `Location permission denied! Enable GPS to continue.` |
| **Approved Inspection Lock** | `Approved on 03 Nov 2026, 14:20 WAT by Amara Bello. This record is immutable. To amend a finding, create a corrected version linked to this inspection.` | `You cannot edit this item anymore.` |
| **Zero-Activity Report Period** | `No scheduled inspections or work orders were recorded for [Client Account Name] between [Start Date] and [End Date]. All [N] registered properties and [M] assets remain on the active register.` | `No data found.` / *(blank page)* |

## Interaction Primitives

1. **Two-Tier Select Discipline (`select-native` vs. `dropdown-editorial`)**:
   - Use **Tier-1 `.cc-select`** for all simple enumerations (Asset Condition, Asset Status, Work Order Priority, Status Filters, Report Format). This guarantees instant native wheel/sheet pickers on Android and iOS field phones.
   - Use **Tier-2 `.cc-dropdown`** (`<button role="combobox">`) only where secondary metadata or status chips are required to disambiguate choices (Client account scope switcher showing active property count; Custodian/Technician selector showing role and active job count; Template selector showing version number and category).
2. **Append-Only Location & Custody Mutations (`AD-7`, `AD-8`)**:
   - Updating a Property's location or an Asset's Custodian never overwrites a field in place without history. Both actions open a lightweight `modal-dialog` that displays the current value, captures the new value + source/note, and upon save immediately prepends the new entry to the surface's `timeline-feed` while keeping all prior readings visible.
3. **Inspection Fault -> Maintenance Request -> Work Order Chain (`FR-11`, `FR-12`, `FR-13`)**:
   - Inside `checklist-runner`, marking any question `Fail` reveals an inline `Raise maintenance request` drawer (aliased under `modal-dialog`) without leaving the inspection page. Submitting the drawer creates the linked Maintenance Request and optional assigned Work Order and displays a linked badge (`WO-2026-0142 · Assigned`) with a `min-height: 40px` `View WO` action right on the checklist item row so the supervisor never loses their place in a 40-question walkthrough.
4. **Honest Multi-Visit Work Order Progress vs. Evidence-Gated Completion (`FR-14`, `FR-15`, `AD-11`)**:
   - `WorkOrderDetail` separates **Record partial progress / place on hold** (`.cc-button--secondary`) from **Complete work order** (`.cc-button--teal`).
   - A Technician who cannot finish a repair in one visit logs `work_performed`, `outstanding_work`, and `delay_reason` and transitions status to `in_progress` or `on_hold`. No photo is required to log partial progress.
   - Clicking **Complete work order** checks whether at least one photo attachment exists on the work order. If zero photos are attached, the completion button highlights the inline `evidence-uploader` with a clear 3-part alert and blocks transition to `completed` until the photo upload succeeds.
5. **Asynchronous Report Compilation & Polling (`FR-17`, `FR-18`, `AD-14`, `AD-15`)**:
   - Clicking `Compile report preview` on `ReportCompiler` compiles the client account's period data synchronously to render the on-screen HTML editorial preview.
   - Clicking `Export PDF & CSV` dispatches the background export job (`concurrency = 1` on the worker to protect VPS memory) and activates `async-export-banner` polling every `3s` until the signed R2 download links are ready.
6. **Strictly Banned Patterns**:
   - Infinite scroll on any table or timeline (use `pagination`).
   - Optimistic UI state transitions on financial/compliance mutations (`Approve & sign off inspection`, `Complete work order`, `Assign custodian`). Always await server confirmation and audit commit before showing the confirmed state.
   - Hover-only action buttons (every row action must be reachable via keyboard focus and visible on mobile touch viewports).
   - Stacking modal dialogs (`modal-dialog` over `modal-dialog`).

## Accessibility Floor

Accessibility is a hard pilot-readiness requirement (`PRD NFR-5.4` and `docs/design/design-context.md`), targeting **WCAG 2.2 Level AA** across both desktop and mobile web surfaces:

- **Contrast Guarantees (Text & Non-Text SC 1.4.3 & SC 1.4.11)**: All text, badge, and control boundary combinations meet or exceed WCAG 2.2 AA (`15.8:1` Ink Navy body on White; `12.1:1` Heading Navy on White; `5.86:1` Accent Teal `{colors.teal}` `#126E6A` on White and `5.19:1` on `{colors.teal-wash}` `#EAF3F4`; `6.68:1` Interactive Blue Dark `{colors.blue-dark}` `#365F91` on regular-weight subtitles and links; `5.18:1` Muted text on White; `4.66:1` to `6.31:1` across all five `.cc-status--*` badge foreground/background pairs; and `3.95:1` `{colors.border-control}` `#6E7E91` on all form inputs, selects, dropdown triggers, and filter chips). Editorial Blue (`{colors.blue}`, `4.02:1`) is restricted strictly to large bold headings (`>=20px` bold / `24px` bold) and decorative/structural `1px` rules.
- **Touch Target & Typography Floor (SC 2.5.8)**: Every primary interactive control (`.cc-button`, `.cc-input`, `.cc-select`, `.cc-dropdown__trigger`, `.cc-filter`, `.cc-tab`, segmented checklist radio buttons, mobile `.cc-page-link` cells, mobile `View WO` links, and `mobile-quick-task-bar` items) maintains a minimum height of **`40px` (`{spacing.control-height}`)**, while compact table row buttons (`.cc-button--small`) expand from `32px` on desktop to `min-height: 36px` with `8px` spacing on mobile (`<=760px`). Core workflow copy never drops below **`14px` (`{typography.body-sm.fontSize}`)**, compact metadata/eyebrows never drop below **`12px` (`{typography.status-badge.fontSize}`)**, and mobile prose and form controls (`.cc-input`, `.cc-select`, `.cc-textarea`, `.cc-dropdown__trigger`) expand to **`16px` (`{typography.body-base.fontSize}`)** at `@media (max-width: 760px)` so iOS Safari never auto-zooms the viewport.
- **Keyboard, Focus Not Obscured & Dragging Alternatives (SC 2.4.1, SC 2.4.7, SC 2.4.11, SC 2.5.7)**:
  - Every page starts with `.cc-skip-link` (`Skip to main content`).
  - `html` enforces `scroll-padding-top: 80px; scroll-padding-bottom: 72px;` so sticky headers and mobile bottom bars never obscure focused elements.
  - Every interactive element exhibits the universal `:focus-visible` indicator (`outline: 2px solid var(--cc-blue-dark); outline-offset: 1px; box-shadow: var(--cc-focus);`).
  - `<PropertyMap>` pairs map pin dragging with explicit Latitude/Longitude numeric inputs and a `Use current device GPS` button (SC 2.5.7).
- **Semantic Structure & Screen Readers**:
  - Data tables use proper `<table>`, `<caption>`, `<thead scope="col">`, `aria-sort`, and `<tbody>` markup so screen readers announce column headers alongside cell values.
  - Status badges (`.cc-status`) always include visible text words (`Completed`, `Overdue`, `In progress`, `Draft`). Status is never conveyed by colour alone.
  - Dynamic status changes (`async-export-banner` transitions, `checklist-runner` sync badge, `evidence-uploader` progressbar with `role="progressbar"`, non-blocking GPS fallback notices, and interrupted-upload recovery bars) use `role="status" aria-live="polite"` (or `role="alert"` for errors) so assistive technologies announce updates without losing focus.

### Nigerian Mobile Network Resilience (NFR-5.2)
- **Zero External Webfonts**: Uses system `Arial` and `Georgia` exclusively, generating zero render-blocking font requests.
- **Client-Side Photo Downscaling & Interrupted Upload Recovery**: High-resolution phone camera photos (`4` to `12 MB`) are compressed client-side to `<=1920px` WebP/JPEG (`~180` to `350 KB`) before upload over 3G/4G connections, with an `interrupted-retry` recovery bar retaining the compressed blob in memory if mobile signal drops.
- **Paginated Payloads & Scoped Partial Reloads**: All index tables paginate (`20` rows per page); map pins load lightweight coordinate/ID tuples; Inertia tab switches use partial reloads (`only: [...]`) to minimize payload size across ~110ms to 150ms Nigeria-to-Frankfurt RTT.

## Inspiration & Anti-patterns

### Lifted From (Positive Reference Patterns)
- **Management Consulting & Property Strategy Dossiers (`DESIGN_SYSTEM.md`)**: Deep Ink Navy (`{colors.navy}`) table headers with white serif type, thin `1px` `{colors.rule-blue}` rules under display titles, uppercase `{colors.teal}` kickers, and a single pale teal `.cc-callout` (`{colors.teal-wash}`) for executive takeaways.
- **UK.GOV / GOV.UK Design System**: High-contrast visible labels (`<label for="...">`) above every input, `>=3:1` input border contrast, explicit 3-part validation error summaries, native `<select>` preference for mobile reliability, and zero reliance on colour alone for status.
- **Linear / Stripe Dashboard Table Discipline**: Deterministic keyboard navigation, URL-synced filters, cursor pagination, `tabular-nums`, and zero decorative chrome competing with tabular data.

### Explicitly Rejected Anti-Patterns
- **Rejected (SaaS "Rainbow Metric Card" Dashboards)**: No grids of brightly coloured KPI cards with circular progress rings, sparklines, or heavy drop shadows. Summary cards stay white (`{colors.surface}`) with `1px solid {colors.border}`, using `.cc-card--emphasis` (`3px` `{colors.blue}` top border) on at most one primary card.
- **Rejected (Pill Badges & Rounded Consumer Controls)**: No `border-radius: 9999px` status pills or `12px`-radius buttons. All controls use `2px` to `3px` (`{rounded.sm}` / `{rounded.DEFAULT}`); tables and callouts use `0px` (`{rounded.none}`).
- **Rejected (Blocking Work on GPS or Postcode Lookup)**: Poor indoor generator-room GPS reception or an unverified NIPOST postcode must **never** block a user from saving a Property (`FR-2`), uploading photo evidence (`FR-21`), or completing a Work Order (`FR-15`).
- **Rejected (Silent In-Place Overwrites of History)**: Updating a Property's coordinates (`FR-3`), changing an Asset's Custodian (`FR-6`), or amending an approved Inspection (`FR-11`) never overwrites historical records; the UI always surfaces the append-only audit/version trail.
